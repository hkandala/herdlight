## Source of truth and protocol

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes, layout, floating panes, web addresses, plugin panes and (on macOS) machines. ([Data](/docs/data)) | Clients with their own copy drifted. A fresh device rebuilds from herdr. | App-owned tabs or layout. |
| D2 | One primitive per machine: run a command and use its stdio. ([The primitive](/docs/talking-to-herdr#the-primitive)) | One path for local, remote macOS and iOS; herdr's own remote method. | A daemon, relay or bridge of our own on the machine. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. ([The primitive](/docs/talking-to-herdr#the-primitive)) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. ([Requests](/docs/talking-to-herdr#requests)) | One path; no socket lookup; the cost hides behind the snapshot pacing. | A direct local socket; socket forwarding. |
| D5 | Events only mean "read the snapshot again". Status events only for agent panes; no focus events. Snapshot reads are paced per machine: one in flight, 100 ms debounce with a 500 ms maximum wait, one trailing read for events during a read. ([Events](/docs/talking-to-herdr#events)) | One code path; each status entry costs herdr a poll; a steady flow of events cannot starve updates. | Applying deltas; subscribing to every pane; polling `session.snapshot` (an ssh run and a herdr process every second on every machine, even when nothing changes). |
| D6 | Apply snapshots to stable observable objects with hand-written lenient models. ([Reconcile](/docs/talking-to-herdr#reconcile)) | One status change redraws one row. | One big state value; code generation. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab and shown floating cards of the selected machine (Mac: plus recently shown tabs, D46). ([Terminal plane](/docs/talking-to-herdr#terminal-plane)) | Public, per pane, works over SSH, survives moves. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`. |
| D8 | One control rule: the Mac opens `control` without takeover and watches if refused; iPhone and iPad open `observe`. Any device takes control (`--takeover`) on the first key press, paste, click or tap in the card, or Take back. A watcher stays a watcher until its user acts. A Mac that becomes inactive keeps its streams; iOS releases them in the background. ([One controller per pane](/docs/talking-to-herdr#one-controller-per-pane)) | One controller and one PTY size per pane. Looking on a phone never resizes the PTY. Looking on a Mac pins it to the card size, which is accepted. | Taking over on open; automatic takeover; `control` on every device. |
| D38 | Refuse herdr older than 0.9.3; a banner for newer protocols; `--session` on every herdr argv. ([Finding herdr](/docs/talking-to-herdr#finding-herdr-on-a-machine)) | Old herdr lacks what we use; no inherited variable can redirect a command. | A read-only mode. |
| D40 | Every `call()` has a 10 s timeout. On a timeout the app kills the bridge process or channel and runs `ping`. Long-lived streams have no timeout; the 30 s `ping` checks them. ([Requests](/docs/talking-to-herdr#requests)) | A dead SSH link after a network change must not hang drags, writes and plugin calls. | No timeout; a timeout on streams. |
| D46 | The Mac keeps the `control` streams of recently shown tabs, about 24 terminals, least recently shown first out; the hidden ones stop drawing but keep reading their streams. ([What streams](/docs/talking-to-herdr#what-streams)) | Coming back to a tab resizes nothing: no second redraw of a full-screen app while a herdr TUI is also attached. | Releasing on leaving a tab (each return resized the PTY twice); streaming every pane. |

## Machines

| # | Decision | Why | Rejected |
|---|---|---|---|
| D15 | macOS SSH = system `ssh`, one ControlMaster per host started on purpose, forwarding off, a bundled askpass script. ([macOS](/docs/machines#macos)) | The user's setup works; one prompt per host; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D16 | macOS machines come from `herdr session list` and `herdr machine list`; adding runs `herdr machine add` in a terminal card. The Mac app requires herdr installed on the Mac. ([Add a machine](/docs/ui/add-a-machine), [macOS](/docs/machines#macos)) | herdr stores machines, installs itself and starts the server, and needs a terminal for its questions. | An app machine list on macOS. |
| D17 | iOS uses Citadel with a Secure Enclave key; machines in `UserDefaults`; the Mac via Remote Login. ([iOS](/docs/machines#ios)) | Pure Swift; the key cannot leave the device; no new mechanism. Spike S7 tests the exec channels first. | libssh2 + OpenSSL; a relay. |
| D39 | **Changed by D47.** On This Mac the app never starts herdr. It shows the command to run in a terminal. Remote machines keep a **Start herdr** button (over SSH). Children are always signalled by pid. ([Checks on connect](/docs/machines#checks-on-connect)) | A server started by the app makes the app the "responsible process" for every agent (macOS privacy prompts would name Herdlight) and shares its process group. | Starting the local server from the app. |
| D47 | On This Mac the app starts a session's server (New Session, picking a stopped session, **Start**) as a one-shot launchd job in the user's GUI domain: `launchctl bootstrap gui/<uid>` with a plist holding `herdr --session S server`, `RunAtLoad`, no `KeepAlive`, `ProcessType` `Interactive` (the default throttles CPU and I/O of the server and every agent in it), stderr to `~/Library/Logs/Herdlight/<S>.log`, label `dev.hkandala.herdlight.herdr.<S>`; an older job of that label is booted out first, never a running one (a server that answers `ping` is left alone). Amends D39. ([Checks on connect](/docs/machines#checks-on-connect)) | launchd is the server's parent and its responsible process (checked with `responsibility_get_pid_responsible_for_pid`: the server is its own, its pane shells point to the server), so privacy prompts never name Herdlight; it has its own process group and outlives the app. `herdr session stop` ends it for good: launchd keeps the job loaded, not running. | `launchctl submit` (keeps the job alive: launchd restarted the server after `herdr session stop`); `nohup` or a double fork from the app (the app stays the responsible process); opening a Terminal window running herdr. |
| D43 | A machine is one herdr session: one entry in the machine list and one sidebar page. Sessions on one host share one SSH connection and its channel budget. ([What a machine is](/docs/machines#what-a-machine-is)) | herdr's own unit is the session; one connection per host keeps one prompt and one channel budget. | One connection per session; one machine per host. |

## Layout and terminals

| # | Decision | Why | Rejected |
|---|---|---|---|
| D9 | libghostty-spm draws terminals, as a pinned build with uHerdr's response-suppression patch. ([Dependencies](/docs/platform#dependencies)) | Best quality on both platforms. The patch stops a second answer to terminal queries that herdr already answered. | SwiftTerm as the main renderer (kept as a fallback); xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. ([Layout and sizing](/docs/layout)) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own: the zoomed card fills its tab's page, drawn by the split tree (each split above it stacks its sides; the others stay hidden at their size). ([Zoom](/docs/ui/window#zoom), [Zoom is the app's own](/docs/layout#zoom-is-the-apps-own)) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. In the split tree, no terminal view changes host and no other PTY resizes. | `pane.zoom`; a separate layer (its terminal view did not come back on restore). |
| D12 | One tab = one page in the strip. ([Swiping](/docs/ui/swiping)) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own, per device. ([Selection and "seen"](/docs/layout#selection-and-seen-are-the-apps-own)) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. herdr sets `completion_seq` on a finish and clears it at the next status change. ([Status area](/docs/status#status-area-and-notifications)) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D41 | Closing a pane asks first unless the pane runs only its shell. Closing a tab or workspace always asks. ([Writes](/docs/talking-to-herdr#writes-are-herdr-calls)) | A close kills processes on every device and cannot be undone. | Asking only when an agent works; never asking. |
| D42 | Rex-like behavior follows gorex: one tab status slot (× on hover > ▲ > ✓ > ◔), a static ◔, double-click a divider to reset it to 0.5, ⌃⌘= to make splits equal, the window title from the selected tab. ([Main window](/docs/ui/window)) | gorex is a readable Rex copy; a static glyph avoids constant redraws. gorex is not a glass reference. | An animated working glyph; several glyphs per tab. |

## Floating panes, chat and status

| # | Decision | Why | Rejected |
|---|---|---|---|
| D28 | Floating panes = panes in a tab labeled `hl:float`; float and dock are `pane.move`; cards inside the main window; frames in memory. ([Floating panes in herdr](/docs/floating-panes)) | herdr keeps which panes float; any pane kind can float; nothing stored. | herdr popups; label markers; a window per floating pane. |
| D29 | Chat = the agent's transcript tailed on the machine + `agent.prompt`; parsers for pi, Claude Code and Codex; a screen-text chat for every other agent or terminal pane. Web and plugin panes have no chat view. ([Chat view](/docs/chat-view)) | What every working chat view does; any agent or terminal pane can switch. | Per-agent prompt parsers; parsing the screen into fake messages. |
| D30 | The blocked panel sends a key only if the agent is still blocked and the prompt text is unchanged. ([Sending and answering](/docs/chat-view#sending-and-answering)) | The prompt may have changed on another device. | Sending without a check. |
| D31 | Notifications are made by the app from snapshot changes; `.passive` while the pill shows (except with VoiceOver or Switch Control); no iOS push in v1. ([Notifications](/docs/status#notifications)) | herdr sends its own only to TUI clients; no double alerts; push needs a relay. | herdr's private notifications; dropping banners. |
| D32 | Floating pills: one non-activating `NSPanel`, one pill with a glyph per agent, a pill card that is the compact chat view, peeks that never take the keyboard, opaque. ([Floating pills](/docs/ui/pills), [how they work](/docs/status#floating-pills-how-they-work-macos)) | One proved the shape; never steal a keystroke; glass renders flat in an inactive app. | A pill per agent; a SwiftUI window; glass pills. |

## Look and platform

| # | Decision | Why | Rejected |
|---|---|---|---|
| D33 | **Changed by D44.** Dark theme only: opaque near-black window, opaque cards, dark-tinted glass on chrome. ([Theme and accessibility](/docs/ui/theme-and-accessibility)) | An all-dark look with no colored windows. | A translucent window; a light theme in v1. |
| D44 | Dark theme only, frosted: a dark-tinted behind-window blur for the window, translucent dark pane cards with a hairline border on it. The sidebar sits flat on that background (no panel); Liquid Glass only on the tab marker and popovers. Replaces D33's opaque window and cards. ([Theme and accessibility](/docs/ui/theme-and-accessibility)) | The user's reference look (Rex): the desktop shows through softly, cards float; only the cards stand out from it. | Opaque window and cards; glass on the cards; a glass sidebar panel; a light theme in v1. |
| D45 | One title-bar row: sidebar toggle, session picker (the session name; its machine is in the list it opens), then the tab capsules while the sidebar is hidden, ⌘ and + on the right. It starts after the traffic lights, at the window edge in full screen. While the sidebar is shown, tabs are its rows under workspace section headers. ([Main window](/docs/ui/window)) | The reference look; tabs show once, where there is room. | A tab bar and a sidebar at the same time; agent rows in the v0 sidebar. |
| D48 | ⌘K (and the title-bar ⌘ button) opens the command palette: a centered glass panel that lists tabs, workspaces and running sessions, filtered as you type, arrows to move, Enter to jump, Esc to close. Card actions join it later. ⇧⌘N makes a new session, ⌘T a new tab, ⌘W closes the keyboard card. ([Keyboard](/docs/ui/theme-and-accessibility)) | ⌘K is the palette key in Rex, Slack, Linear and VS Code's quick open; herdr owns the screen, so Terminal's ⌘K (clear) has nothing to clear. | ⇧⌘P (VS Code's command palette, less known outside editors); ⌘P. |
| D34 | One multiplatform target, macOS 26 and iOS 26, one main window. ([One codebase](/docs/platform#one-codebase)) | Liquid Glass and `WebView`; no fallbacks; no control fights. | Separate apps; back-deploying; several main windows in v1. |
| D35 | Horizontal gestures belong to the strip; the PaneViewRegistry owns every view. ([Making the strip work](/docs/platform#making-the-strip-work)) | Terminals and web views would eat the swipe; SwiftUI would destroy views. | Each view handling its own scroll. |
| D36 | iPhone shows one pane per page and opens agents in chat. ([iPhone and iPad](/docs/ui/iphone-and-ipad)) | Splits do not fit; chat needs no PTY. | Shrinking splits onto a phone. |

## Pane kinds and plugins

| # | Decision | Why | Rejected |
|---|---|---|---|
| D18 | Everything is a plugin: one registry, manifest shape and picker; terminal, agent and web are native core plugins. ([Everything is a plugin](/docs/plugins)) | One model for every pane kind without JavaScript cost for core panes. | Special-casing core kinds; herdr TUI plugins in the picker. |
| D19 | Plugin UI = TypeScript + React in one JSContext per card, rendered as native SwiftUI through a component kit. ([Plugin UI](/docs/plugins/plugin-ui)) | Native look and behavior; ~3 MB per card; the JS reaches only the injected API; works on iOS. | React in a web view; React Native; native Swift plugins; ExtensionKit. |
| D20 | Plugins live in the app, installed from a git URL or a linked folder; the app never runs npm. ([Packages](/docs/plugins/packages)) | One install per device for every machine; no setup on any machine; a simple dev loop. | herdr plugins on each machine; an in-app store. |
| D21 | A plugin pane is a herdr pane labeled `hl:<plugin>[/<pane>]#<iid> <arg>`. A placeholder is typed only once the new pane's shell is in front; it is cosmetic. ([Labels and instance ids](/docs/plugins/labels)) | The label is durable and readable; the iid survives moves and restarts. | Metadata tokens; an app-side pane list. |
| D22 | Bigger plugin state lives in a JSON file on the pane's machine, keyed by iid; preferences stay per device. ([State and restore](/docs/plugins/state)) | Shared by every device, survives reinstalls, no sync service. | Labels for everything; app storage. |
| D23 | After every rename or state write, a `hl_rev` metadata token tells other devices to refresh. ([Web page](/docs/plugins/web-page), [State and restore](/docs/plugins/state)) | A rename sends no event; a token change does. | Polling; a terminal-title trick. |
| D24 | Plugin API = `exec` on the card's own machine, pane context, `setArg`, instance state, the snapshot, preferences, toasts, confirmed `open`, clipboard copy, navigation. ([Plugin API](/docs/plugins/api)) | Covers diff, git history and Markdown; nothing more. | Network, storage, a herdr call API, plugins outside panes in v1. |
| D25 | Plugin security: one VM per card bound to its machine; one permission (`exec`) described honestly; consent at install and on new permissions, keyed by id and source; a This Mac confirm; no network or HTML from the app; user-gesture rule for `open` and the clipboard; a watchdog. ([Plugin security](/docs/plugins/security)) | The user sees exactly what they grant; the app adds no reach beyond `exec` on the pane's machine. | Finer permissions that do not hold; claiming a sandbox that `exec` cannot give. |
| D26 | iOS v1 ships core plugins only. ([Plugins on iOS](/docs/plugins/ios)) | Downloaded code is an App Store review risk. | User plugins on iOS in v1. |
| D27 | Web page = core plugin with label `web:<url>`. A label set elsewhere loads only after a click, unless the user approved that origin for this machine. Per-machine data stores; remote `localhost` through forwards on other ports. ([Web page](/docs/plugins/web-page)) | Durable marker; no request leaves the device without the user; machines stay apart. | Auto-loading every label; SOCKS (WebKit never proxies loopback); same-port forwards. |
| D37 | The agent picker lists the available `integration.list` entries. ([Agent](/docs/plugins/terminal-and-agent#agent)) | One call; herdr checks the `PATH`. | Probing every agent with `command -v`. |
