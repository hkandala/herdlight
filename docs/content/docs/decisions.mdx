---
title: "Design decisions"
description: "Every design decision, why, and what was rejected"
---

| # | Decision | Where | Why | Rejected |
|---|---|---|---|---|
| D1 | herdr is the source of truth for workspaces, tabs, panes, layout, floating panes, web addresses, plugin panes and (on macOS) machines. | [Principles](/docs#principles), [Data: app vs herdr](/docs/data) | Clients with their own copy drifted. A fresh device rebuilds from herdr. | App-owned tabs or layout. |
| D2 | One primitive per machine: run a command and use its stdio. | [The primitive](/docs/talking-to-herdr#the-primitive) | One path for local, remote macOS and iOS; herdr's own remote method. | A daemon, bridge or relay on the machine. |
| D3 | Every remote command goes through a base64 envelope run by `sh`. | [The primitive](/docs/talking-to-herdr#the-primitive) | The login shell may be fish, where POSIX quoting is not safe. | Quoting argv into the login shell. |
| D4 | Control plane = `herdr --session S remote-api-bridge` on every machine, one call per request. | [Requests](/docs/talking-to-herdr#requests) | One path; no socket lookup; the cost hides behind the event debounce. | A direct local socket; socket forwarding. |
| D5 | Events only mean "re-read the snapshot"; status events only for agent panes; no focus events. | [Events](/docs/talking-to-herdr#events) | One code path; each status entry costs herdr a poll. | Applying deltas; polling; subscribing to every pane. |
| D6 | Apply snapshots to stable observable objects with hand-written lenient models. | [Reconcile](/docs/talking-to-herdr#reconcile) | One status change redraws one row. | One big state value; code generation. |
| D7 | Terminal plane = `herdr terminal session control/observe` by `terminal_id`, for the selected tab and shown floating cards of the selected machine. | [Terminal plane](/docs/talking-to-herdr#terminal-plane) | Public, per pane, works over SSH, survives moves. | herdr's private client socket; `terminal attach` in a PTY; polling `pane.read`. |
| D8 | One control rule: open as control without takeover, watch if refused, take over on the first key press or Take back. | [Terminal plane](/docs/talking-to-herdr#terminal-plane) | One controller and one PTY size per pane; looking never steals a pane. | Taking over on open; automatic takeover. |
| D9 | libghostty-spm draws terminals. | [Dependencies](/docs/platform#dependencies) | Best quality on both platforms. | SwiftTerm; xterm.js in a web view. |
| D10 | Layout = herdr's split tree rebuilt from the flat snapshot; resize = `layout.set_split_ratio`. | [Layout and sizing](/docs/layout) | Ratios live in herdr; no extra calls. | App-owned sizes; `layout.export` per tab. |
| D11 | Zoom is the app's own, drawn as a layer. | [Zoom](/docs/ui/zoom), [Zoom is the app's own](/docs/layout#zoom-is-the-apps-own) | `pane.zoom` moves herdr's focus, marks the tab seen and blocks moves. | `pane.zoom`. |
| D12 | One tab = one page in the strip. | [Swiping](/docs/ui/swiping) | Matches herdr and Cube. | Panes wider than the window in one long scroller. |
| D13 | The app never calls herdr's focus methods; selection and "seen" are the app's own. | [Selection and "seen" are the app's own](/docs/layout#selection-and-seen-are-the-apps-own) | Each focus call moves every attached herdr TUI. | Focusing on click or swipe. |
| D14 | "Finished, not seen" = `completion_seq` not null and different from the seen value; the first sighting counts as seen. | [Selection and "seen" are the app's own](/docs/layout#selection-and-seen-are-the-apps-own), [Status area and notifications](/docs/status#status-area-and-notifications) | herdr skips `done` when a TUI watches the tab; the counter restarts with herdr. | Waiting for `done`; a "greater than" test. |
| D15 | macOS SSH = system `ssh`, one ControlMaster per machine started on purpose, forwarding off, a bundled askpass script. | [macOS](/docs/machines#macos) | The user's setup works; one prompt per machine; no path back to the Mac. | `ControlMaster=auto`; a Swift SSH library on macOS. |
| D16 | macOS machines come from `herdr session list` and `herdr machine list`; adding runs `herdr machine add` in a terminal card. | [Add a machine](/docs/ui/add-a-machine), [macOS](/docs/machines#macos) | herdr stores machines, installs itself and starts the server, and needs a terminal for its questions. | An app machine list on macOS. |
| D17 | iOS uses Citadel with a Secure Enclave key; machines in `UserDefaults`; the Mac via Remote Login. | [iOS](/docs/machines#ios) | Pure Swift; the key cannot leave the device; no new mechanism. | libssh2 + OpenSSL; a relay. |
| D18 | Everything is a plugin: one registry, manifest shape and picker; terminal, agent and web are native core plugins. | [Everything is a plugin](/docs/plugins) | One model for every pane kind without JavaScript cost for core panes. | Special-casing core kinds; herdr TUI plugins in the picker. |
| D19 | Plugin UI = TypeScript + React in one JSContext per card, rendered as native SwiftUI through a component kit. | [Plugin UI](/docs/plugins/plugin-ui) | Native look and behaviour; ~3 MB per card; the JS reaches only the injected API; works on iOS. | React in a web view; React Native; native Swift plugins; ExtensionKit. |
| D20 | Plugins live in the app, installed from a git URL or a linked folder; the app never runs npm. | [Packages, install and updates](/docs/plugins/packages) | One install per device for every machine; no host setup; a simple dev loop. | herdr plugins on each machine; an in-app store. |
| D21 | A plugin pane is a herdr pane labelled `hl:<plugin>[/<pane>]#<iid> <arg>` with a placeholder process. | [Labels and instance ids](/docs/plugins/labels) | The label is durable and readable; the iid survives moves and restarts. | Metadata tokens; an app-side pane list. |
| D22 | Bigger plugin state lives in a JSON file on the pane's machine, keyed by iid; preferences stay per device. | [State and restore](/docs/plugins/state) | Shared by every device, survives reinstalls, no sync service. | Labels for everything; app storage. |
| D23 | After every rename or state write, a `hl_rev` metadata token tells other devices to refresh. | [Web page](/docs/plugins/web-page), [State and restore](/docs/plugins/state) | A rename sends no event; a token change does. | Polling; a terminal-title trick. |
| D24 | Plugin API = `exec` on the card's own machine, pane context, `setArg`, instance state, the snapshot, preferences, toasts, confirmed `open`, clipboard copy, navigation. | [Plugin API](/docs/plugins/api) | Covers diff, git history and Markdown; nothing more. | Network, storage, a herdr call API, plugins outside panes in v1. |
| D25 | Plugin security: one VM per card bound to its machine; one permission (`exec`) described honestly; consent at install and on new permissions, keyed by id and source; a This Mac confirm; no network or HTML from the app; user-gesture rule for `open` and the clipboard; a watchdog. | [Plugin security](/docs/plugins/security) | The user sees exactly what they grant; the app adds no reach beyond `exec` on the pane's machine. | Finer permissions that do not hold; claiming a sandbox that `exec` cannot give. |
| D26 | iOS v1 ships core plugins only. | [Plugins on iOS](/docs/plugins/ios) | Downloaded code is an App Store review risk. | User plugins on iOS in v1. |
| D27 | Web page = core plugin with label `web:<url>`; a label set elsewhere loads only after a click; per-machine data stores; remote `localhost` through forwards on other ports. | [Web page](/docs/plugins/web-page) | Durable marker; no request leaves the Mac without the user; machines stay apart. | Auto-loading every label; SOCKS (WebKit never proxies loopback); same-port forwards. |
| D28 | Floating panes = panes in a tab labelled `hl:float`; float and dock are `pane.move`; cards inside the main window; frames in memory. | [Floating panes](/docs/floating-panes) | herdr keeps which panes float; any pane kind can float; nothing stored. | herdr popups; label markers; a window per floating pane. |
| D29 | Chat = the agent's transcript tailed on the machine + `agent.prompt`; parsers for pi, Claude Code and Codex; a screen-text chat for every other pane. | [Chat view](/docs/chat-view) | What every working chat view does; any pane can switch. | Screen scraping; per-agent prompt parsers. |
| D30 | The blocked panel sends a key only if the agent is still blocked and the prompt text is unchanged. | [Sending and answering](/docs/chat-view#sending-and-answering) | The prompt may have changed on another device. | Sending without a check. |
| D31 | Notifications are made by the app from snapshot changes; `.passive` while the pill shows (except with VoiceOver or Switch Control); no iOS push in v1. | [Status area and notifications](/docs/status#status-area-and-notifications) | herdr sends its own only to TUI clients; no double alerts; push needs a relay. | herdr's private notifications; dropping banners. |
| D32 | Floating pills: one non-activating `NSPanel`, one pill with a glyph per agent, a card that is the compact chat view, peeks that never take the keyboard, opaque. | [Floating pills (macOS)](/docs/ui/pills), [Floating pills: how they work (macOS)](/docs/status#floating-pills-how-they-work-macos) | One proved the shape; never steal a keystroke; glass renders flat in an inactive app. | A pill per agent; a SwiftUI window; glass pills. |
| D33 | Dark theme only: opaque near-black window, opaque cards, dark-tinted glass on chrome. | [Theme](/docs/ui/theme) | An all-dark look with no coloured windows. | A translucent window; a light theme in v1. |
| D34 | One multiplatform target, macOS 26 and iOS 26, one main window. | [One codebase](/docs/platform#one-codebase) | Liquid Glass and `WebView`; no fallbacks; no control fights. | Separate apps; back-deploying; several main windows. |
| D35 | Horizontal gestures belong to the strip; the PaneViewRegistry owns every view. | [Making the strip work](/docs/platform#making-the-strip-work) | Terminals and web views would eat the swipe; SwiftUI would destroy views. | Each view handling its own scroll. |
| D36 | iPhone shows one pane per page and opens agents in chat. | [iPhone and iPad](/docs/ui/iphone-and-ipad) | Splits do not fit; chat needs no PTY. | Shrinking splits onto a phone. |
| D37 | The agent picker lists the available `integration.list` entries. | [Agent](/docs/plugins/terminal-and-agent#agent) | One call; herdr checks the `PATH`. | Probing every agent with `command -v`. |
| D38 | Refuse herdr older than 0.9.3; a banner for newer protocols; `--session` on every herdr argv. | [Finding herdr on a machine](/docs/talking-to-herdr#finding-herdr-on-a-machine) | Old herdr lacks what we use; no inherited variable can redirect a command. | A read-only mode. |
