A native macOS and iOS app that gives [herdr](https://github.com/herdrdev/herdr)
a modern interface. herdr stays the backend: it owns every workspace, tab,
pane, terminal and agent. The app draws them, drives them, and keeps as
little state of its own as it can.

- Name: **Herdlight**. These pages are the design. There is no app code yet.
- Targets: herdr 0.9.3 (protocol 22), macOS 26, iOS and iPadOS 26. The Mac
  app needs herdr 0.9.3 or newer installed on the Mac, even to reach remote
  machines.
- See it: the [interactive overview](/overview/index.html) has working
  mock-ups of the main screens on one page.
- Evidence for the claims is in the repository's
  [`resources/research/`](https://github.com/hkandala/herdlight/tree/main/resources/research)
  and [`resources/inspirations/`](https://github.com/hkandala/herdlight/tree/main/resources/inspirations)
  folders (see [Sources](/docs/reference/sources)).

## The problem

People run many coding agents (Claude Code, Codex, pi) at once, often on
several machines. herdr keeps those agents alive in panes on each machine and
knows when each one is working, blocked or done (the app shows these as
working, needs you and finished). But herdr's interface is a terminal UI: one
machine at a time, keyboard-first, and nothing when you are away from the
terminal.

## What we build

One app for Mac, iPad and iPhone that shows every herdr machine at once:
- a sidebar of machines and workspaces with every agent's status;
- a strip of tabs you swipe through, with resizable panes;
- panes for terminals, agents, web pages and plugins;
- a chat view for any agent or terminal pane;
- floating panes over the strip;
- floating status pills on the Mac screen edge when you are in another app.

On iPhone, v1 shows status while the app is open. Alerts while the app is
closed need push notifications, which come later.

## Principles

1. **herdr is the source of truth.** If herdr can hold a piece of state, herdr
   holds it. A fresh app on a new device rebuilds everything from herdr.
   Everything the app keeps for itself is listed in
   [Data: app vs herdr](/docs/data).
2. **Use what exists.** herdr's API and CLI, OpenSSH, Apple's frameworks. No
   daemon, relay or server of our own.
3. **Everything is a plugin.** Terminal, agent and web page are core plugins.
   Yours are TypeScript and React, drawn as native SwiftUI.
4. **The simplest thing that works.** Each shortcut we take on purpose is
   marked "Simpler choice" and says when to revisit it.
